# GitHub Repo Evaluator

用最少的时间判断一个 GitHub 仓库是否值得使用。三选一：**下载 / 观望 / 关掉**。

## 核心原则

KISS - Keep It Simple, Stupid。评估应该像扫表一样快，不是做尽职调查。

## 评估维度

### 1. 做什么 → 看 README + 演示页面

**判断:**
- 用途、截图、适用人群说清楚了
- 有成品演示，不只是愿景

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| 用途明确，有截图/演示 | 只有愿景，没有使用结果 |
| 适用人群清晰 | 说了一堆概念但不知道怎么用 |

### 2. 能不能用 → 看 Releases + 安装说明

**判断:**
- 有正式版本（非 just commits）
- 有系统安装包或明确的安装命令

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| Releases 有版本号和安装包 | 只有源码，需要手动编译且没有说明 |
| 一条命令能跑起来 | 环境依赖复杂且没文档 |

### 3. 还活着吗 → 看版本记录 + 最近更新

**判断:**
- 最近 6 个月有更新
- 版本说明清晰（非 "fix stuff"）

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| 版本记录清楚，分阶段 | 一年没更新，外部依赖已变化 |
| Issues 有人回应 | 同类报错反复出现无人处理 |

### 4. 坑多吗 → 看 Issues + 安全政策

**判断:**
- 开放 Issues 少或正在被修复
- 权限要求解释清楚

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| Issues 有人回应 | 一上来索要重要密钥或登录状态 |
| 权限说明清晰 | 安全政策缺失 |

### 5. 热度可信吗 → 看 Star + 维护状态

**判断:**
- Star 多且维护状态好
- 不是虚高（只有 Star 其他都差）

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| Star 高，维护活跃 | Star 很高但两年没更 |
| 社区参与度高 | Issues 积压严重 |

### 6. 有机会吗 → 看 Issues + Discussions

**判断:**
- 有真实需求（用户有痛点）
- 有改进空间但不大

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| 问题重复，用户已有临时方案 | 只有一条随口建议，没有实际场景 |
| 有明确的 feature request | 需求不明确或市场规模太小 |

### 7. 赚钱空间 → 看安装、模板、部署

**判断:**
- 能交付明确结果
- 有持续维护的商业模式

**信号:**
| 可以继续 | 应该停下 |
|---------|---------|
| 模板/部署有明确变现路径 | 把免费文件换个包装重新卖 |
| 有付费版本但免费版够用 | 依赖不明确，难以部署 |

## 决策框架

```
输入: GitHub URL

1. 抓取关键信息:
   - README.md (用途)
   - Releases (版本状态)
   - Issues (用户痛点)
   - 贡献者/更新时间 (活跃度)

2. 按维度打分 (每项 +1/-1/0)

3. 汇总决策:
   - 总分 >= 3: 下载
   - 总分 1-2: 观望
   - 总分 <= 0: 关掉
```

## 输出格式

```
# [Repo Name] 评估报告

## 三步定位
1. 它做什么: [一句话描述]
2. 能用吗: [是/否/部分]
3. 还维护吗: [是/否]

## 详细评估
| 维度 | 状态 | 依据 |
|-----|------|-----|
| 用途清晰度 | ✅/⚠️/❌ | ... |
| 版本状态 | ✅/⚠️/❌ | ... |
| 维护状态 | ✅/⚠️/❌ | ... |
| 问题响应 | ✅/⚠️/❌ | ... |
| 热度可信度 | ✅/⚠️/❌ | ... |
| 需求真实度 | ✅/⚠️/❌ | ... |
| 商业可行性 | ✅/⚠️/❌ | ... |

## 最终决策
**[下载] / [观望] / [关掉]**

理由: [一句话]
```

## 使用示例

**输入:**
```
帮我看看 https://github.com/tiangolo/fastapi 值不值得用
```

**输出:**
- 快速抓取 README、Releases、Issues
- 按维度打分
- 输出简洁评估报告
- 给出三选一决策

## 注意事项

- 不要花时间通读源码
- 不要做详细的代码审查
- 不要尝试运行项目
- 只做"扫一眼能不能用"的判断
