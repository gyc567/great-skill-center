# 多平台适配分发引擎 (Platform Adapter)

## Overview

"一篇长文吃遍全网"的实现引擎。核心逻辑源自 Charlie Hills 的 newsletter → multi-platform 模型：

```
源内容（公众号长文/newsletter）
    ├→ 微信朋友圈（精华观点）
    ├→ 小红书（图文笔记）
    ├→ LinkedIn（双语专业贴）
    ├→ Twitter/X（线程）
    └→ 知乎（问答改编）
```

一条源内容 → 5 个版本，各平台格式自适配，发布建议附带最佳时段。

## When to Use

触发词：
- "把这篇文章分发到其他平台"
- "多平台适配" / "跨平台"
- "一鱼多吃" / "repurpose"
- "adapt to all platforms"
- "分发"

## 工作流程

### Step 1: 读取源内容

用户提供源内容（可以是 vault 中的一篇笔记、一段文本、或一个 Obsidian 路径）。

如果是 vault 中的文件，用 `mcp_orbitos_vault_read` 读取。

### Step 2: 提取可分发要素

从源内容中提取：
- **核心观点**（1 句话总结）
- **最有力的数据/案例**（1-2 个）
- **金句**（最有传播力的一句话）
- **情绪锚点**（引发共鸣/愤怒/惊讶的点）

### Step 3: 生成各平台版本

按以下规格逐一生成：

#### 1. 微信朋友圈 (300 字以内)
```
风格：松弛、像朋友聊天
格式：3-4 句话 + 1 个 emoji + 换行节奏
不要：链接、号召关注、正式语气
要点：让人感觉"顺手刷到的真实分享"
```

#### 2. 小红书 (500-800 字)
```
风格：亲切 + 实用 + emoji 分行
格式：标题 + 正文分点 + 话题标签
必备：开头用 emoji，中间用小标题分段，结尾 Call to Action
不要：过于正式、长段落
要点：收藏价值 > 观点深度
```

#### 3. LinkedIn (中英双语, 1000 字)
```
风格：专业但不僵硬
格式：英文 hook（留悬念空行）+ 中文/双语正文 + 多空行分段 + 3-5 个 hashtag
不要：中文标题、大段英文
要点：第一行必须用空行制造 curiosity gap
```

#### 4. Twitter/X 线程 (5-8 条，每条 200 字)
```
风格：紧凑、每一条都有 hook
格式：1/N 编号 + 短句 + 最后一条引导互动
不要：长篇大论
要点：每条必须能独立传播（别人转发单条也有价值）
```

#### 5. 知乎回答 (如果源内容可回答某个问题)
```
风格：专业、有结构、引用数据
格式：先抛结论 → 分点论证 → 总结
不要：情绪化、像朋友圈
要点：假装在回答一个具体问题
```

### Step 4: 发布计划

输出一张发布日程表：

```
## 发布计划

| 时间 | 平台 | 版本 | 最佳时段 |
|------|------|------|---------|
| 周一 | 公众号 | 源长文 | 07:30 或 21:00 |
| 周二 | 小红书 | 图文版 | 12:00 或 19:00 |
| 周三 | LinkedIn | 双语版 | 周二-周四 8:00-10:00 |
| 周四 | Twitter/X | 线程版 | 9:00 或 17:00 |
| 周五 | 朋友圈 | 精华版 | 20:00-22:00 |
```

### Step 5: 保存到 vault

将所有版本保存到 vault 中：

- 路径：`30_知识库/分发-YYYY-MM-DD.md`
- 包含：源内容链接、各平台版本、发布计划

## 各平台文案特点速查

| 平台 | 字数 | 语气 | 段落 | 标签 | emoji | 链接 |
|------|------|------|------|------|-------|------|
| 公众号 | 不限 | 正式/半正式 | 短段+空行 | 不需 | 适度 | 可放 |
| 朋友圈 | <300 | 松弛/真实 | 3-4句 | 不需 | 1-2个 | 不放 |
| 小红书 | 500-800 | 亲切/有用 | emoji分行 | 5-10个 | 大量 | 不放 |
| LinkedIn | 800-1200 | 专业/亲民 | 多空行 | 3-5个 | 少量 | 可放 |
| Twitter/X | 200/条 | 紧凑/有力 | 单行 | 0-2个 | 少量 | 可放 |
| 知乎 | 1000+ | 专业/结构 | 分点 | 不需 | 极少 | 可放 |

## Common Pitfalls

1. **简单复制粘贴**：直接把公众号文章发到小红书 = 必死。每个平台有各自的语言体系。
2. **朋友圈太长**：超过 300 字会被折叠，读者只看到前 2 行。
3. **LinkedIn 中文标题**：LinkedIn 中国区用户的 TL 上，中文标题看起来像广告。用英文 hook。
4. **小红书没有标签**：小红书的流量 30%+ 来自标签搜索，不带标签等于自断流量。
5. **忘记调整人设**：公众号可能是"专家"人设，朋友圈要是"朋友"人设，同一句话换个语气。
