> **把一个复杂答案，渲染成一页自包含的 HTML 讲解图。**
> 模型只写 Markdown 草稿，CLI 负责全部排版、配色、暗色模式和图表坐标。

## 🎯 它解决什么问题

回答一个复杂问题时，纯文字有天然的短板：**流程看不全、对比记不住、层级读不懂**。

这个 Skill 的做法很克制 —— **你不写 HTML，只写 Markdown**：

```
你写：扩展 Markdown 草稿
CLI 做：排版 · 配色 · 暗色模式 · SVG 自动布局 · STE 受控写作检查
```

**结果**：单文件 HTML，135KB 左右，无外部 CDN 依赖，双击就能看，还能导出 PDF / PNG。

### 什么时候该用

| 场景 | 例子 |
|------|------|
| **≥3 个互相关联的概念** | 讲清楚它们怎么互相影响 |
| **有流程 / 协议 / 调用链 / 状态流转** | 带分支或多角色的请求链路 |
| **跨 ≥3 维度的对比** | 技术选型、优缺点取舍、"能做/不能做"清单 |
| **有层级或时间演进** | 架构演进、生命周期 |
| **用户说** | "没看懂 / 画个图 / 讲讲原理 / 讲清楚点" |

> 📌 **判断原则：问题越"需要看图才懂"，就越该出页面。**
> 页面很快也很便宜 —— 不确定的时候出页面就对了。

## ✨ 核心能力

### 一、14 种组件，覆盖绝大多数可视化需求

| 组件 | 用途 |
|------|------|
| `flow` | 流程图（**自动布局坐标**，还能标 `+`/`-`/`~` 显示改动） |
| `er` | ER 图（实体关系） |
| `sequence` | 时序图 |
| `tree` | 目录 / 代码结构树 |
| `timeline` | 时间线 |
| `limits` | 每行一个值 vs 一个上限 |
| `chart` | `bar` / `line` / `pie`（最多 6 系列、24 行） |
| `annot` | 标注 |
| `kv` | 键值表 |
| `callout` | 重点提示框 |
| `ask` | 交互式提问 |
| `image` | 本地图片（PNG/JPG/GIF/WebP/AVIF/SVG，≤5MB） |
| `code` | 引用**真实存在的代码**（`src=` + `lines=`，CLI 直接读文件，不用手抄） |
| `diff` | 代码 diff（支持 `+`/`-`/空格/`@@`） |

> 📌 **代码块支持 `src=`** —— CLI 会去读磁盘上的真实文件，选 10-40 行最能说明问题的部分。**代码是真的，不是你手打的。**

### 二、4 套主题 × 明暗模式

`auto`（默认）/ `blueprint` / `shadcn` / `paper`，加 `light` / `dark`。
还能 `am theme add` 从主题目录装自定义主题（带 sha256 + 对比度校验）。

### 三、STE100 受控写作检查

`am lint` 单独跑写作检查。渲染时默认以 `style: 80` 模式**只警告不拦截**，`--style strict` 时不合规的草稿**不产页面**，每条警告都附具体修法。

### 四、3Blue1Brown 风格讲解视频

`am video` 渲染成 3b1b 风格讲解视频播放页，可导出 `--mp4` / `--webm`。
有**章节条**（点 chip 跳场景）、场景切分、旁白（ElevenLabs / 本地 / 系统语音）。

### 五、页面补丁 —— 改一面不动全页

`am patch page.html --panel "标题"` 只替换某一个 `##` 面板，**原地覆盖**，
保留原页的主题、明暗模式和 STE 风格。不用重写整页。

### 六、导出

`am export` → A4 PDF / PNG 切片（给聊天软件发图）。

## 🚀 快速开始

```bash
# Node.js 20+ 就够，零 npm 依赖
node scripts/am.mjs --version

# 渲染一页
node scripts/am.mjs render draft.md --no-open

# 改一个面板
node scripts/am.mjs patch page.html --panel "面板标题" <<'EOF'
## 面板标题
新内容
EOF

# 只跑写作检查
node scripts/am.mjs lint draft.md

# 导出
node scripts/am.mjs export page.html --pdf out.pdf --png pngs/
```

**输出位置**：`~/.answer-me-with-html/pages/`（可用 `AM_HOME` 改）

## 🧩 它是怎么教 Agent 用的

这个 Skill 最值得学的地方是**流程纪律**，不是组件本身：

### 1. 先决定「要不要出页面」

不是所有回答都该有图。纯闲聊、一句话答案、用户明确要纯文本 —— **不出页面**。

### 2. 代理报告 ≠ 用户回复

> *"如果父 agent 或协调器委派了研究、实现、评审或进度报告 —— 返回它要的结构和发现，不要渲染页面。"*

这条很关键：**避免子 agent 疯狂生成页面淹没主流程**。

### 3. Always-on 模式

在 `CLAUDE.md` / `AGENTS.md` 里加一行规则，就能让每次给出结论时都自动附页面：

```
[answer-me-with-html always-on]
```

此时门槛降低 —— 只要有结论就出页面，**用 `--no-open` 避免弹窗打断用户**，而且**先渲染页面再写回复**，页面链接放回复的最后一行。

### 4. 只写草稿，不写 HTML

> *"**不要手写 HTML / CSS / SVG。**"*

布局、配色、图表坐标全部由 CLI 处理。手写就是给自己埋坑。

### 5. 写完要复查

SKILL.md 里有明确的「写好之后」检查清单：每个事实只说一次（表格/图里有的就别在文字里重复）、
面板要能被扫读、代码要真实、图表优先用 `chart` 而不是手写 SVG。

## ⚠️ 实测坑点

| 坑 | 说明 |
|----|------|
| **Node 版本** | 需要 **Node.js 20+**。低版本会明确报错并给出各平台安装命令 |
| **`-o` 是文件不是目录** | `am render -o page.html` —— 写目录会报错 |
| **沙箱写入失败** | 沙箱只允许写工作区时，CLI 会自动存到系统临时目录并打 `!` 行提示；需要放工作区就加 `-o "<绝对路径>/.tmp/answers/topic.html"` |
| **有警告的草稿不会自动打开浏览器** | STE 或代码有警告时页面不会自动弹出，要手动开 |
| **`am clean` / 更新命令不要自己跑** | SKILL.md 明确要求：**先问用户**，等用户同意再执行。CLI 自带节流（清理提示 7 天一次，更新提示 3 天一次） |
| **`am serve` 不要自己起** | 服务由用户启动，Agent 只在输出有 `link:` 行时把那个链接用起来 |
| **图片必须是本地文件** | 远程图片不会加载；且**永远不要生成或臆造图片** |
| **`<script>` 不执行** | html 代码块里的 `<script>` 不会跑，页面只允许 am 自己的脚本 |
| **改面板时找不到 `#am-source`** | 面板找不到或页面没有源草稿时，**文件保持不变**（安全失败） |
