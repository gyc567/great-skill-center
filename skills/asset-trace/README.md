## 🎯 它解决什么问题

公开渠道能查的东西散在十几个站点，能查什么、查到什么程度、哪些根本查不到，通常靠个人经验。
**查漏了不会报错，但会直接影响执行方案。**

本 Skill 把这些经验固化成流程：

> **能机器查的自动查，查不到的明说去哪拿，未查的绝不写成"没有"。**

---

## 🏗️ 三层渠道

| 层级 | 内容 | 处理方式 |
|------|------|----------|
| **A 机器可查** | 法律数据库 MCP（元典）、企查查类连接器 | Skill 内自动执行 |
| **B 半自动** | 执行信息公开网四库、中登网、司法拍卖、公告网、国家企业信用信息公示系统、第三方风险库 | **不硬爬**（反爬多变易失效），生成"操作路径卡"交人工，贴回结果后二次分析 |
| **C 公开不可查** | 银行流水、不动产、车辆、证券、保险、社保公积金、婚姻财产 | 自动生成**调查令方向清单** |

---

## 📋 五步流程

1. **输入体检** —— 主体分流（自然人 / 法人）；自然人强制同名甄别
2. **连接器探测** —— 探测元典/企查查可用性，不可用即降级并标注，**禁止含糊写"均已核验"**
3. **批量检索** —— 自然人 15 线 / 法人 6 层穿透，逐线执行并记录来源与查询日
4. **线索评估** —— P0 立即行动 → P3 观察，附对应法律动作与"可执行距离"
5. **报告产出** —— 六件套：画像卡 / 线索池 / **查全度核对表** / 人工待办 + 调查令清单 / 行动 SOP / 核验声明

### 案卷前提四项（Step 1 之前核对）
1. **执行依据已生效且有可执行内容**（生效日期决定加倍利息起算日与时效表述）
2. **执行程序状态**（未申请 / 在册 / 终本 / 终结 / 中止 —— 终本可随时恢复，**不受申请执行时效限制**）
3. **债权构成分列**（本金 / 一般利息 / 加倍部分利息，日万分之一点七五）
4. **主体锚点齐全**（法人＝统一社会信用代码；自然人＝身份证号）

---

## 🛡️ 五条核心纪律

| # | 纪律 |
|---|------|
| 1 | **禁"未查=没有"** —— 凡未实际查询的线，状态只能标 `⏳未查` 并写入人工待办，禁止写成"无记录" |
| 2 | **状态四标** —— `✅已核验`（须附来源+查询日）｜`❗冲突`（两说并陈）｜`⏳未查`（须写原因）｜`⛔公开不可查`。**禁用"部分核实""基本确认""大致查到"** |
| 3 | **同名甄别前置** —— 自然人未锁定身份前不产出任何财产结论 |
| 4 | **法条不引记忆** —— 注明"以现行有效版本为准" |
| 5 | **只指方向不做结论** —— 公开途径查明的是"线索"而非"财产证明"，措辞用"疑似/待核实" |

## 📊 查全度基线（核对表的行数标准）

> **"全"指的是基线必查集跑满，不是全矩阵 34 线全跑。**

| 主体 | 基线 | 条目 |
|------|------|------|
| **法人** | 12 项 | F1 工商登记 · F2 年报实缴认缴 · F3 股东实控人 · F4 对外投资穿透 · F5 裁判文书（原告/被告分查）· F6 执行案件 · F7 终本案件 · F8 失信 · F9 限高 · F10 股权冻结/出质 · F11 知识产权（含作品著作权）· F12 变动与公告 |
| **自然人** | 9 项 | N1 同名甄别 · N2 裁判文书（双向）· N3 执行案件 · N4 终本 · N5 失信 · N6 限高 · N7 限制出境/边控 · N8 任职与持股 · N9 对外债权 |
| **扩展项** | E1–E17 | 分支机构 / 司法拍卖 / 询价评估 / 招投标 / 欠税 / 劳动仲裁 / 送达公告 / 舆情 / 知产官方法律状态 / 房产公开面 / 婚姻与配偶 / 消费行为 / 动产抵押 / 融资租赁 / 土地权属 / 企业财务 / 招聘与经营痕迹 |

**行数自检**：`核对表行数 = 基线 12（或 9）+ 启用扩展项数`；少于基线即交付不合格。

## 🔧 交付前机械校验（闸门）

```bash
python3 scripts/validate_report.py <报告.md> [报告2.md ...]
```

校验四项，**任一 FAIL 退出码 1，不得交付**：

| # | 校验项 |
|---|-------|
| 1 | **行数闭合** —— 核对表含基线全集（F1–F12 / N1–N9），行数 = 基线 + 启用扩展项 |
| 2 | **✅ 完整性** —— 每个 ✅ 行的来源列非空且含日期（行级查询日 **或** 表级「查询日」声明） |
| 3 | **统计闭合** —— 状态统计行数字 = 核对表逐行实际计数 |
| 4 | **⛔ 对应性** —— 每个 ⛔ 行都能在「调查令」章节找到关键词命中（**无孤儿**） |

> 📌 只判机械项；日期语义（出生日期 ≠ 查询日）、来源可信度仍需模型自检与人工判断。

## ⚠️ 实测坑点（本次入库时验证）

| 坑 | 说明 | 应对 |
|----|------|------|
| **上游示例报告跑不过自家闸门** | `examples/示例报告-虚构脱敏.md` 用 v1.6.1 的校验器跑会 FAIL：部分 ✅ 行缺行级查询日、缺「状态统计」行 | 上游 v1.6.1 加严了校验但示例未同步。**以 `references/07-报告输出模板.md` 为准**，示例仅作结构参考 |
| **核对表行 ID 必须是 `F`/`N`/`E` + 数字** | 写成 `—` 或 `C 层调查令项` 的行**不会被解析**，⛔ 统计与对应性校验会失效 | 每一行都要有规范 ID（`F1`…`F12` / `N1`…`N9` / `E1`…`E17`） |
| **「查询日」可表级声明** | 不必每行都写日期 —— 核对表标题下写 `**查询日：2026-10-22**` 即可让所有 ✅ 行通过校验 | 表级声明更省事，也更不易漏 |
| **svg2png 是 macOS 专属** | 走 `osascript -l JavaScript` + AppKit，**Linux/Windows 不可用** | Linux 下用 `rsvg-convert` / `inkscape` / `cairosvg` 替代 |
| **不做浏览器自动化硬爬 B 层站点** | 反爬策略多变，投入产出比低且易失效 | 按设计走"操作路径卡 + 人工贴回" |

- **不替代**法院网络查控、律师调查令、现场调查 —— 产出是"公开面的天花板 + 下一步路径"
