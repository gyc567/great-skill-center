# FABE 销售法则 —— 产品特点到客户价值的翻译器

> 品牌：AI Skills 创作小店

## 一、是什么

FABE 是一套经典的产品销售话术工具，把**产品客观特点**转化成**客户能感知到的价值**，四个环节形成闭环：

```
F (Feature)     产品是什么、有什么
  ↓
A (Advantage)   这个特点能干什么
  ↓
B (Benefit)     对我（客户）有什么好处
  ↓
E (Evidence)    拿出什么证明
```

---

## 二、四个字母的准确定义

| | 含义 | 回答的问题 | 常见错误 |
|---|------|-----------|---------|
| **F** = Feature（特征/属性） | 产品客观事实、固有特性 | 产品是什么、有什么 | —— |
| **A** = Advantage（优势/作用） | 由特征衍生的优点、独特能力 | **这特点有什么用** | ❌ 把 F 重说一遍 |
| **B** = Benefit（利益/好处） | 给客户本人带来的实实在在的收益 | **对我有什么好处** | ❌ 继续说产品 |
| **E** = Evidence（证据/证明） | 佐证前面好处、打消疑虑 | **凭什么让我相信** | ❌ "品质保证"这类空话 |

---

## 三、核心逻辑

```
「产品有什么」→「它能干什么」→「对你有什么收益」→「拿出证据证明靠谱」
```

**适合**：保险、实物产品、服务、SaaS、课程 —— 任何需要写产品介绍和销售话术的场景。

## 四、完整套用示例

### 示例 1：洗地机（实物产品）

| 环节 | 内容 |
|------|------|
| **F** | 自带热风烘干滚刷 |
| **A** | 洗完不会潮湿、不容易发霉异味 |
| **B** | 你不用手动拆开晾晒滚刷，更省心，家里更卫生 |
| **E** | 产品检测报告、买家实测视频 |

### 示例 2：增额终身寿险（保险）

| 环节 | 内容 |
|------|------|
| **F** | 这是一款增额终身寿险，有固定递增 |
| **A** | 比普通年金险更灵活，可以按需随时申请部分领取现金价值（比如孩子上学、结婚） |
| **B** | 提前给孩子储备教育/婚嫁资金，减轻未来经济压力 |
| **E** | 出示保单现金价值表、条款、案例 |

### 示例 3：SaaS（本 Skill 自举）

| 环节 | 内容 |
|------|------|
| **F** | 内置校验器，四级递进机械可查 |
| **A** | 写话术时能当场发现"F/A 混淆"和"空话证据"，不用等客户反问才改 |
| **B** | 你交付给客户的每一份话术都过了闸门，退单和返工少一半 |
| **E** | 15 项自检测试，正例反例双向验证，测试报告可直接给客户看 |

## 五、标准工作流程

### Step 1：收集产品事实

先列出**客观、可核实**的事实清单（这是 F 的原料）：

- 材质 / 规格 / 参数
- 功能 / 配置 / 授权范围
- 条款 / 保障责任 / 服务承诺
- 资质 / 认证 / 奖项

> ⚠️ **只写能拿出证据的事实。** 拿不出证据的特性不要写进 F —— 后面 E 环节会接不上。

### Step 2：逐条做 F→A 翻译

对每一条事实问：**「这个特点，能干什么？」**

| 坏（复述 F） | 好（说清能力） |
|--------------|---------------|
| 不锈钢材质，3000W 大功率电机 | 顽固污渍一遍过，20 分钟搞定一屋子 |
| 采用进口材料 | 耐磨度提升，日常使用不易留痕 |
| 支持多端登录 | 出门用手机、办公室用电脑，进度不丢 |

> 📌 **A 必须出现能力类表达**（可以 / 能够 / 支持 / 相比 / 自动 / 一次…）。
> 如果 A 里全是材质、功率、容量、参数 —— 你还停在 F。

### Step 3：把 A 落到客户身上（B）

问：**「所以呢？这对我意味着什么？」**

翻译公式：

```
[场景/处境] + [因此可以怎样] + [省掉/避免什么]
```

| 弱 | 强 |
|----|-----|
| 提升效率，降低成本，优化体验 | 你不用每周花两小时对账，月底直接看报表 |
| 家里更卫生 | 你不用手动拆开晾晒滚刷，更省心，家里更卫生 |
| 资产安全有保障 | 孩子上学的钱提前锁定，不用担心将来收入波动 |

> ⚠️ **B 里不能出现"提升效率""降低成本""优化体验""赋能""打造闭环"** ——
> 这些是最典型的 AI 空话，客户听不出任何具体变化。

### Step 4：为每条 Benefit 配证据（E）

问：**「凭什么让你相信？」**

必须落到**可出示的具体材料**：

| 证据类型 | 例子 |
|---------|------|
| 检测报告 | 第三方检测、SGS、CNAS 报告 |
| 案例 | 客户案例、实测视频、买家秀、使用记录 |
| 凭证文件 | 保单、合同、条款、证书、发票、保修卡 |
| 数据表格 | 现金价值表、价格表、费率表、参数表 |
| 演示 | 现场演示、免费试用 |
| 评价 | 用户评价、评分、权威认证、获奖 |
| 对比 | 横向对比表、实测数据 |
| 公开背书 | 媒体报道、上榜、官方认可 |

> ⚠️ **"很多客户都说好"不是证据。** "品质保证"不是证据。必须能真的拿出来。

### Step 5：跑校验器（**必做**）

```bash
python3 scripts/validate_fabe.py 话术.md
```

退出码 `0` = 通过，`1` = 有问题，每条问题都附具体修法。

**不要跳过这一步。** 这一步存在的意义就是：肉眼很难发现的"F/A 混淆"和"空话套话"，脚本一秒就能指出来。

## 六、输出格式

### 格式 A：单品话术卡

```markdown
## 【产品名】

- **F（特征）**：<客观事实>
- **A（优势）**：<这特点能干什么>
- **B（利益）**：<对客户的好处>
- **E（证据）**：<可出示的具体材料>

**一句话话术**：<把 F→A→B→E 压缩成一句可直接说出口的话>

**客户可能的疑问**：
- 「这个真的假的？」→ 答：<出示 E>
- 「太贵了」→ 答：<拆解到 B>
```

### 格式 B：多品对比话术

对比时 **F 用同一维度**，否则没法比：

| 维度 | 产品 A | 产品 B | 产品 C |
|------|-------|-------|-------|
| F：<同一维度> | | | |
| A：<各自优势> | | | |
| B：<各自对客户> | | | |
| E：<各自证据> | | | |

### 格式 C：异议应对

用 FABE 补齐缺口：

```
客户异议：「太贵了」
  → 重讲 B：<算给客户看，省下的是 X>
  → 补 E：<证明它值这个价>
```

## 七、常见错误对照表

| 症状 | 错误写法 | 正确写法 |
|------|---------|---------|
| F/A 混淆 | A：不锈钢材质，3000W 电机 | A：顽固污渍一遍过 |
| B 说产品 | B：采用进口材料，工艺先进 | B：你用得更久，不容易坏 |
| B 是空话 | B：提升效率，降低成本，优化体验 | B：你不用每周花两小时对账 |
| E 是空话 | E：品质保证，值得信赖 | E：第三方检测报告 + 1000+ 实测视频 |
| E 模糊 | E：很多客户都说不错 | E：具体客户案例 + 数据对比表 |
| 缺环节 | 只说了 F 和 B | 四级必须齐全 |

## 八、场景适配

| 行业 | E 环节常用证据 |
|------|--------------|
| 保险 | 保单现金价值表、条款、监管备案 |
| 家电/实物 | 检测报告、参数对比表、买家实测视频 |
| SaaS | 演示、试用、标杆客户案例、第三方评测 |
| 课程/培训 | 学员作品、结业数据、导师资质 |
| 服务/咨询 | 合同条款、服务承诺 SLA、过往项目成果 |
| 金融 | 费率表、监管备案、历史收益数据 |

**选证据的原则**：客户能当场看到、能当场验证、能当场拿走。

## 九、扩展用法

### 9.1 一句话电梯话术

把四级压成一句：

```
F + A + B + E 压缩 → "自带热风烘干滚刷，洗完不用拆晾，家里的滚刷不会发霉，有检测报告和买家实测视频。"
```

### 9.2 按客户角色改写

同一产品，对不同角色重心不同：

| 角色 | B 重心 | E 重心 |
|------|-------|-------|
| 决策者 | 成本、风险、回报 | 案例、对比数据 |
| 使用者 | 省事、好用 | 演示、试用 |
| 付款人 | 值不值、够不够 | 报价单、条款 |

### 9.3 话术卡入库

产出的单品话术卡建议存成 `fabe-cards/<产品名>.md`，方便复用和迭代。

## 十、常见问题

**Q：B 可以不说"你"吗？**
可以。关键是**落在客户的处境上**，不一定用第二人称。
「提前给孩子储备教育/婚嫁资金，减轻未来经济压力」—— 没有"你"字，但受益人明确。

**Q：一个产品有 10 个特点，是不是要写 10 组 FABE？**
不必。按客户的**关注点**分组，每个关注点一组。销售时间有限，3-5 组足够。

**Q：F 和 E 都用数据，会不会重复？**
不会。F 的数据是**产品参数**，E 的数据是**佐证材料**。F 说"续航 5000mAh"，E 出示"续航实测报告"。

**Q：校验器 FAIL 了但我觉得话术没问题？**
先看它指出的具体问题。如果是误判（比如产品名里带"材质"），可以调整措辞。
但**大多数时候它是对的** —— F/A 混淆和空话恰恰是肉眼最容易放过的。

## 十一、校验器参考

```bash
# 校验一份话术
python3 scripts/validate_fabe.py 话术.md

# JSON 输出（便于批量处理）
python3 scripts/validate_fabe.py 话术.md --json

# 内置示例自检
python3 scripts/validate_fabe.py --demo

# 跑测试套件
python3 tests/test_validate_fabe.py
```

### 五项机械校验

| 校验项 | 判定 |
|--------|------|
| 四级齐全 | F/A/B/E 都存在 |
| A 不复述 F | 与 F 词重叠 ≥50% 且 ≥2 词，或只含客观参数无能力描述 → FAIL |
| B 落到客户 | 无客户视角表述，或以 AI 空话开头 → FAIL |
| E 可出示 | 未命中任何证据类型，或含空话 → FAIL |
| 无空话套话 | 汇总所有层级的问题数 |

- FABE 是经典销售框架（源自 E. St. Elmo Gapner 的 FAB 法则，后由 Walter G. Salesman 等人发展）。
- 本 Skill 只提供**结构化表达工具**，不替代产品专业性，也不保证商业结果。
- **金融、保险、医疗等受监管行业**：话术中的收益描述、比较表述、证据出示方式必须符合当地监管规定。
