# 论文改写专利时的审核前置规则

将论文改写成专利时，不要把审核当成最后一步。应在 intake、映射、权利要求、说明书扩写和终稿检查阶段持续执行风险识别。

## 1. 先判断专利类型

改写开始时先判断当前材料更像哪一类专利：

- 发明专利：方法、算法、系统、控制逻辑、功能流程、技术方案
- 实用新型：产品结构、形状、构造改进
- 类型不明确：材料不足，暂不下结论

如果材料主要是算法或处理流程，不要误导性地按实用新型去写。

## 2. 三性判断要写成风险评估

在论文改写场景中，通常只能做初步判断。默认不要直接写“完全符合”或“完全不符合”，而应写成：

- 新颖性风险：低 / 中 / 高 / 信息不足
- 创造性风险：低 / 中 / 高 / 信息不足
- 实用性风险：低 / 中 / 高 / 信息不足

每一项都说明依据来源，例如：

- 来自论文原文
- 来自附图或结构关系
- 来自作者备注
- 来自合理泛化
- 仍待用户确认

除非用户提供了正式检索结果或明确要求并完成检索，否则不要把风险评估写成结论性法律判断。

## 3. 论文贡献不等于专利创新点

改写时强制区分：

- 学术贡献
- 技术效果
- 可保护的技术特征

以下内容通常不能直接当作保护核心：

- 实验结果
- 精度提升比例
- 排名领先
- 论文结论性描述

应优先抽取导致这些结果的步骤、模块、结构关系、参数控制或协同机制。

## 4. 问题-目的-方案-效果必须闭环

在映射阶段检查以下四项是否一致：

- 背景技术中的问题
- 发明目的
- 技术方案
- 技术效果

常见错误包括：

- 背景里说的是问题 A，方案解决的是问题 B
- 发明目的过大，但方案只覆盖其中一部分
- 技术效果写得很强，但正文没有足够技术手段支撑

若闭环断裂，先修结构再继续撰写。

## 5. 技术可行性要边写边核

改写过程中持续检查：

- 关键步骤是否可执行
- 模块关系是否合理
- 输入输出是否闭合
- 参数范围是否有依据
- 原理描述是否违背基本工程、物理或化学常识

不要用“理论上可行”“应当可以”“可能实现”来替代充分公开。

## 6. 保护范围要分层

不要一次性把所有内容写成一个粗糙的独立权利要求。优先拆成：

- 核心独立权利要求
- 优选从属特征
- 替代实施方式
- 备选保护路径

重点防止两类错误：

- 过宽：概括过度，说明书支撑不足
- 过窄：把具体实施例细节写死在独立项里

## 7. 说明书要补足论文天然缺口

论文常缺这些专利必需信息：

- 关键参数
- 触发条件
- 步骤顺序
- 模块连接关系
- 输入输出定义
- 异常处理或可替代方案

发现缺口时应明确提示用户补充，而不是自行虚构。

## 8. 保密边界与公开充分性要同时考虑

对每个敏感细节都要判断：

- 是否必须公开到足以实施
- 是否可以抽象表达而不损害支撑
- 是否属于不宜写入公开文本的商业敏感信息

若某项内容既敏感又对实施必不可少，应明确列为高风险并要求用户确认。

## 9. 图、术语、编号要同步维护

不要等全文写完才想附图和标号。改写时同步维护：

- 图号
- 参考标号
- 模块名称
- 步骤名称
- 摘要、说明书、权利要求中的术语一致性

## 10. 审核输出建议

当用户要求审核结果时，建议使用以下结构：

## 审核结果

### 一、专利类型

[发明专利 / 实用新型 / 类型待确认]

### 二、专利三性风险判断

- 新颖性：[低风险 / 中风险 / 高风险 / 信息不足] - [依据]
- 创造性：[低风险 / 中风险 / 高风险 / 信息不足] - [依据]
- 实用性：[低风险 / 中风险 / 高风险 / 信息不足] - [依据]

### 三、创新点摘要

[核心创新点及与现有技术的区别]

### 四、问题清单

1. [问题描述]
   - 问题类型：[逻辑 / 技术 / 描述 / 保护 / 新颖性 / 创造性]
   - 严重程度：[高 / 中 / 低]
   - 建议修改：[修改建议]

### 五、总体评价

[较好 / 可继续完善 / 需重点修改]

如果证据不足，明确写“基于当前材料的初步判断”。
