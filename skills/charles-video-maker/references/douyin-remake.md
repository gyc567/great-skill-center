# 抖音知识号：复刻爆款，一锅出

> 来源：蔚蓝 WEILANX《Opus 5.5 抖音起号超级保姆级万字教程》（2026-10-18，单号 29 条留 10 条、基本万播以上、最高 108 万）的第五、六章，按本 skill 的工具改写。账号怎么养、怎么判断、怎么投抖加、号废了怎么办，不在这里，在用户的运营手册：`~/Documents/knowledge-base/30-outputs/抖音运营/抖音运营手册.md`（下称「手册」）。
>
> 核心一句：**Opus 自由发挥做出来的东西，大概率不是市场验证过的样子。**所以不从想法出发，从一条正在爆的原片出发：风格一比一，内容不搬，在画面冲击力、质感、卡点三处做得比它更好。

## 什么时候走这条路

用户说「做抖音视频」「抖音一期」「复刻这条」，给的是抖音链接或从抖音下载的原片，或者说「用 <风格名> 做一期：<选题>」。用户说「找选题」「抓热点」「Vibe 有什么在火」「给我 N 个选题」时，先走下面的 **D-1 找选题**。用户给链接就等于同意下载这条原片（下载用任一抖音视频解析站拿无水印版，放进 `source/`）。

**工程目录**：抖音视频一律建在 `~/Desktop/video/vibe-video/<slug>/`（不是通用默认的 `~/Desktop/video/<slug>/`）；同级还有原片库 `_refs/`、风格库 `_styles/`、题材雷达脚本 `_tools/douyin_radar.py`（软链到本 skill 的 `scripts/douyin_radar.py`）。

## 授权到底，不停下来问

调用这条路就等于授权从头做到交付。**不问开工四选，不出三个方案**，只有两种情况停下来问用户：

- 选题查不到任何一手资料

- 同一个工具连续失败两次

## 和默认流程的差别

| 项 | 默认流程 | 抖音知识号 |
|---|---|---|
| 起点 | 想法 / 原内容 / 参考 | 一条正在爆的原片（或风格库里已有的一套风格 + 选题） |
| 规划 | 三方案 + 预览，用户确认 | 跳过，直接蒸馏 → 写 `brief.md` → 制作 |
| 配音 | 默认 Gemini，1.25 倍速 | **默认有人配音**（Gemini TTS 1.25 倍速，走 voiceover-pipeline，配乐垫底）。用户 2026-10-23 依据后台数据定：有配音的视频点赞率更高、2 秒跳出更低。原片没配音也照样配；纯配乐卡点只在用户点名时做 |
| 时长 | 30–60 秒 | **50 秒到 2 分钟**（用户 2026-10-23 定） |
| 画幅 | 竖版 1080×1920 | **跟原片走**。#Vibe知识大赏 主流是横版 1920×1080 / 30fps（2026-10-20 抓的 5 条爆款全是横版） |
| 封面 / 第 0 帧 | 亮底高对比、暴论开头 | 跟蒸馏出的风格走（深色也行）；第 0 帧起顶部挂标题条 |
| 标题 | 覆盖搜索词 | 20 字内、第二人称 + 痛点、留悬念不给答案；封面字和片内标题一致 |
| tags | 5 个，搜索量大的 | 5 个以内，**#Vibe知识大赏 必带** + 2–4 个贴选题的 |
| 交付 | 成片、封面、publish.txt | 再加 3:4 封面、字幕稿、交付报告，并在手册「发布记录」追加一行 |

其余（`render(t)` 只由时间决定、逐镜头自检、渲染脚本、文件命名）照常按 SKILL.md 和 craft-rules.md。

## D-1：找选题（题材雷达）

用户要选题、或者要做视频却没给原片时，从这里开始。脚本 `scripts/douyin_radar.py`（`~/Desktop/video/vibe-video/_tools/douyin_radar.py` 是它的软链），数据落 `~/Desktop/video/vibe-video/_refs/<日期>/`。

**登录**：抖音网页搜索必须登录，不登录一条都抓不到。脚本按「专用浏览器配置 `~/.config/secrets/douyin-pw-profile` 已登录 → 已存 cookie `~/.config/secrets/douyin-cookies.txt` → 从本机 Chrome 现导（必须带 sessionid）→ 弹窗扫码」的顺序自动登录，成功后自动保存，下次不用再登。先跑 `python3 douyin_radar.py login` 确认登录（打印 `logged in as <昵称>`），再抓。**不要把 cookie 搬进别的浏览器反复用**：2026-10-22 把 Chrome 的 cookie 注入自动化浏览器发了几条视频后，服务端把这个会话踢下线了。

**抓两轮，合并排名**：

```
cd ~/Desktop/video/vibe-video/_tools; D=../_refs/$(date +%F)
python3 douyin_radar.py crawl --sort 2 --days 0 --hashtag --name latest_all --out $D   # 最新发布，倒序前 ~100 条 + 话题页
python3 douyin_radar.py crawl --sort 1 --days 7 --name hot7 --out $D                   # 一周内最多点赞
python3 douyin_radar.py rank --name latest_all,hot7 --out $D                           # 总点赞榜 + 72 小时内每小时点赞榜
```

「一天内」筛选网页端只返回个位数，别用。网页接口不给播放量，用点赞、转发、收藏代替。出滑块就请用户拖一下（专用配置过一次后基本不再出）。

**两个选题来源，日常拆解为主（用户 2026-10-23 定）**：头部知识大赏很多就是把大家习以为常的东西拆开讲，不必完全依赖热榜。

- **来源 A · 日常习以为常拆解（主）**：从生活里人人见过、却说不清为什么的现象出发，例如「人为什么要抖腿」「为什么闪电比雷声先到」「掰手指为什么会响、到底好不好」。好选题的特征：一句话就能问出来、每个人都有亲身经验、答案里有一个反常识的点、背后有能核实的研究或物理机制、能画成炫的画面。

- **来源 B · 热榜雷达（辅）**：用下面的脚本看此刻在涨什么，用来校准题材簇和标题写法，也可以直接复刻正在涨的原片。

两个来源出的选题都要过下面的标准。

**选题三问，硬门槛（用户 2026-10-24 认可，依据第一轮自己的数据）**：三个都过才做，写选题表时每条都标出三问各过没过。

1. **自我关联**：标题主语是你，说的是观众对自己的一个怀疑或日常烦恼（总觉得不如别人、越学越差、刷手机停不下来），不是一个外部现象。

2. **翻案加数字**：答案让观众松一口气，不是你不行，是机制；并且带一个具体数字或机制（赢够 6 次、读 3 遍加自测）。

3. **能拿走**：看完有一个能照做的动作、一个能自己验证的方法或一张清单，值得收藏。

**再过一遍许先森Ai 的两条（2026-10-26，用户认可）**：

- **开头问得出一个反常识的问题吗**：一句话问出来，观众一看就想知道答案（照片 0.07 秒怎么过太平洋、二维码会不会被用完）。问不出来的题先别做。

- **因果链短不短**：一条视频只讲一个原理、三步以内讲完。因果链长的（金融机制、多环节的技术原理）观众看一半就走：他讲做空机制 1052 赞、讲 AI 怎么生成回答只有 73 赞。同样是金融，香港保卫战拿了 3 万赞，因为它是一场有对抗、有结局的战役。长链题要做，就改写成故事。

**再过一遍幸福感那条的四条（2026-10-27，用户认可，手册第六节第 10 条）**：全号讨论度最高的是「你人生中幸福感最低的一年，会是几岁」，分享率 2.2%、评论率 0.42%，留存三项全号最好。

- **答案是一个观众能拿自己去对的数字吗**：几岁、几月出生、几点睡，谁都有一个，看的时候一直在想是不是自己。

- **结尾能让人零门槛回复吗**：报一个数字、选一个选项就行。

- **结论能安慰人、让人想转给谁吗**：能安慰别人的题才会被转发，只让自己变好的题停在点赞收藏。

- **对年轻观众是反常识吗**：抖音观众偏年轻，他们默认的那套（越老越不快乐）被数据推翻，反差就是钩子。

物理、数学、历史这类好奇题不是不能做，但要改写成落在人身上：标题先说你，现象只当证据。为什么这么定：开头过关以后，决定爆不爆的是收藏率和点赞率，不是留存。第一轮五条片 2 秒跳出都在 33%～45%，播放却差 50 倍；赢家效应收藏率 1.35%，是金属疲劳的 11 倍，而金属疲劳的留存反而最好。详见手册第六节第 7、8 条。

**挑选标准**（按重要性）：

1. **72 小时涨速榜优先**：发布几小时到三天、每小时点赞高的，说明此刻正在被推；总榜只用来确认题材簇是否被验证过。

2. **零粉 / 小号也能爆的优先**：火的是选题本身，不是老粉在撑。

3. **能画出来**：有一个能演的东西（曲线、天平、点阵、小世界、实验装置）；纯抽象的跳过。

4. **一手资料能核**：一篇论文、一份报告、一个能自己算的数学结论；只有鸡汤没出处的跳过。

5. **能写成「被冤枉 → 翻案」或第二人称痛点**；收藏率、点赞率高的题材簇优先（第一轮数据里它们比分享率更能拉开流量差距）。

6. **去重**：对照手册「七、发布记录」和 `~/Desktop/video/vibe-video/` 已有工程，做过的不再选；同一簇（心理关系 / 物理定律套人生 / 概率数学 / 认知偏差 / 博弈哲学）别连着扎堆。

7. 避开国内合规红线（投资标的、境外开户等）、政治时事、医疗建议。

**交付**：写 `~/Documents/knowledge-base/30-outputs/抖音运营/题材雷达-<日期>.md`：正在涨的原片表（发布小时、点赞 / 转发 / 收藏、作者粉丝、看点）+ 10–20 个选题表（暂定标题、类型：复刻 / 题材迁移、对标原片、一手资料、能画的东西）+ 推荐先做哪几条及理由。要复刻的原片用 `douyin_radar.py get <aweme_id> <名字> --name latest_all,hot7 --out $D` 下载（签名地址几小时内有效，挑完马上下）。

**做成系列（用户 2026-10-24 定）**：视频之间要连贯，同一个系列名、同一个主角、同一个世界，用合集串起来。怎么做见 [douyin-series.md](douyin-series.md)。

**发布与拉数据**：`scripts/douyin_publish.py <slug> "YYYY-MM-DD HH:MM"|now` 上传、填表、定时发布，发布前逐项核对，任一不对就停；用户定的档位是每天 08:00、11:00、14:00、17:00、22:00，定时须在 2 小时后、14 天内，不足 2 小时的档到点用 `now` 直发。`scripts/douyin_stats.py <out.json>` 拉全部已发作品的指标（播放、点赞率、收藏率、分享率、2 秒跳出、5 秒完播、平均观看秒数、涨粉），`scripts/douyin_comments.py <dir> <aweme_id>...` 拉评论和详情。三个脚本都用专用浏览器配置，同一时间只能跑一个。**同一条视频只上传一次**：传上去就有指纹，删掉也还在；remake 要发就把剧照、标题、简介、封面全换掉，当成新视频。2026-10-27 bug 系列 01、02 原版和 remake 各传过一次，发出后只拿到 34 和 23 次播放（手册第六节第 11 条）。

## D0：开工先读手册

读手册的「六、数据结论」（选题和标题按它来）和「五、风格库」（这套风格蒸馏过没有）。风格库在 `~/Desktop/video/vibe-video/_styles/<风格名>/`。原片的风格已在库里，跳过 D1。

## D1：蒸馏风格（机器拆一遍，人眼再拆一遍）

**机器拆**，产物放 `source/`：

```
python3 scripts/analyze_video.py source/ref.mp4 --out source/ref --cells 40          # 镜头切换表 + 联系表
python3 scripts/analyze_video.py source/ref.mp4 --out source/ref-key --frames <每个镜头中点的秒数>   # 每镜头关键帧
ffmpeg -y -i source/ref.mp4 -vn -ac 1 -ar 44100 source/ref-audio.wav
python3 scripts/audio_tools.py beats source/ref-audio.wav > source/ref-beats.json     # 节奏、重拍、鼓点
```

从这些写出：镜头表（第几秒硬切、每镜头多长）、主色板和**强调色**（只看有颜色的像素，黑底上的一点金也要取准）、配乐 BPM 和大重拍落在第几秒。

**人眼拆**：机器只知道哪里变了，不知道为什么好看。先通看联系表，把画面分类（标题卡、图表、实物、大字……）；再逐张看关键帧，放大看字体、描边、发光；把入场、转场、招牌动作各切一小段，一帧一帧数：几帧完成、先快后慢还是匀速、有没有模糊和缩放。

**写进风格库** `~/Desktop/video/vibe-video/_styles/<风格名>/`：

- `style.md` 风格配方卡：配色和字体、背景和质感、版式、标题卡、字幕、转场、节奏、招牌画面，最后一节「没有搬的东西」（原片字幕、标题、创作者名、水印、配乐一律不进库）

- `template.html`：把每个组件都演一遍的 `render(t)` 预览页，之后每期从它起步

- 预览图，并在手册「五、风格库」表里登记一行

**对照至少两轮**：把预览帧和原片同类关键帧左右拼起来（`ffmpeg -i a.png -i b.png -filter_complex hstack qa/cmp.png`），逐项比底色、主色、强调色、字体气质、字号层级、版式位置、留白；动效比同类入场的帧数和缓动。哪里不像改哪里，改完再比。

## 用户的硬要求：开头抓人、画面炫、要反转（2026-10-23）

### 开头 3 秒是全片最重要的部分

抖音极看 2 秒跳出和 5 秒完播，**前几秒的画面和音乐，要是整条视频里投入最多、最强的**，不是「开个头、后面再爆」。具体做法：

**怎么做到「最强」，以拆头部爆款得出的 [douyin-opening.md](douyin-opening.md) 为准**（2026-10-23）：强在**质感和代入**，不在爆炸和满屏动作。

- **画面**：第 0 帧像一张电影截图（3D 渲染或 AI 生成的高质感主画面，有光源、阴影、景深、材质），一个主体、一个主动作或一个慢推镜头；不用 Canvas 2D 手画的线条和色块当主画面。

- **音乐**：第 0 秒就进有情绪的主旋律（氛围钢琴 / 弦乐），不铺前奏；不是鼓点、炸雷堆起来的「响」。头部 5/8 用《千年之后（氛围版）》，发布时在抖音「添加音乐」里选。

- **第一句**：观众一秒认出自己的一个生活场景或疑问，平静陈述，0.3 秒内上字幕；人声可以在 0.3–1 秒内跟上，也可以前 3 秒只有配乐 + 字幕（两种都做样片比）。

- **混音别用单遍 `loudnorm`**：它是动态模式，会把故意做响的开头压到和正文一样响。做法：开头 3 秒的音乐和音效在混音里推高约 4 dB（几乎不压在人声下），再用 `scripts/master_static.py`（静态增益到 -14 LUFS + 只削尖峰的限幅）出 `mix.wav`。验收时量一下 0–3 秒和正文的 RMS，开头应高出约 3 dB 以上（闪电样片实测 -13.7 vs -17 dB）。

- **配乐只用 CC0 采样**：Lemo 采样库里的流行鼓组 `drum_kit`（MuldjordKit）是 CC BY 4.0，用了必须署名，抖音简介里不方便挂；鼓用 CC0 的 `bass_drum`、`snare`、`crash`、`hihat`、`timpani`。合成后看一眼 `score-credits.txt`，只剩 CC0 才算过。

- **自检**：单独把 0–3 秒逐帧渲出来看（`render.py --start 0 --duration 3` + 抽帧拼图），也单独听这 3 秒的混音；这一段不过关，后面做得再好也要先返工。发布后 2 秒跳出率是第一考核指标。

### 其余硬要求

- **前 3 秒必须抓人**：第一句是一个人人都有经验、却答不上来的问题，或一个反常识的结论 / 具体数字；第 0 帧就有完整的主体画面，不能是空镜或只有标题条。

- **画面能多炫有多炫**：每 2–3 秒一个新的视觉动作；至少一个招牌镜头（粒子、光效、镜头推拉、物体爆开 / 拼合、慢动作、剖面透视）；高潮用收暗 → 静止 → 砸字 + 冲击波。

- **能多反转有多反转**：结构上至少一次「你以为 A → 其实是 B」，最好两次（开头的常识被推翻一次，高潮再翻一次）。写进 Gemini 任务单的 role / notes 里，让文案围着反转走。

## D2：资料与文案

复刻的是**选题、结构和节奏、画面语法、音乐调性**；文案重写，画面用风格库重做。

**文案由本地 Gemini 写，Claude 不亲手写**（流程见 [gemini-copy.md](gemini-copy.md)）。Claude 在这一步做三件事：查一手资料、按原片镜头表拆出每句旁白的 slot（时长上限 + 画面）、把下面这些要求写进任务单 `copy/brief.json` 的 role / angle / notes 里，再 `gemini_copy.py gen` → `check`，不过就反馈重写。下面各条是**给 Gemini 的要求**，不是 Claude 自己动笔的提纲。

- **一手资料**：论文至少读到摘要，书读到原段落，搜索结果摘要不算数。每个上画面的数字进核对表（`scripts/factcheck.py`，见 fact-check.md）。知识视频翻车，一般都翻在事实上。

- **结构照原片**：开头怎么抛问题、几秒一个信息点、爆点在哪，按 D1 的镜头表排。

- **锚词**：两到四个字，是这个知识落在普通人生活里的处境，不是术语（讲智猪博弈，锚词是「等」）。开头出现，第二个高潮砸出来，结尾重新定义一次（「等不是懒，是算出来的」）。

- **高潮前那句只说一半**：「你猜，最后是谁吃亏了——」停在破折号上，下一拍画面砸出答案。

- **结尾抛一个人人都有答案的问题**，引到评论区，大号字一直挂到片尾。

- **选题角度**：能写成「被冤枉 → 翻案」就这么写（分享率约是讲机制的 5 倍）；标题避开观众心里早有答案的说法。

- **标题条**：第 0 帧起画面顶部就挂一条标题（「这期讲的就是你」的那句），一直挂到片尾。观众平均只看 10–17 秒，不能等标题卡出来才让人知道讲什么。

## D3：先测音乐，再写画面

- **曲子要有授权**：剪映 / 抖音可商用曲库、免版税曲库，或用 `audio_tools.py` / Lemo 配乐合成。挑和原片同调性的（情绪、BPM 接近）。原片 BGM 只用来测调性和拍点，不进成片。

- `python3 scripts/audio_tools.py beats audio/bgm.wav > audio/beats.json`，整条视频的时间表从这张拍子表里长出来：每句字幕挂在第几拍，每个镜头从第几拍切到第几拍。

- **两个大高潮**放在曲子里最大的两个重拍上（通常一个在 15–20 秒，一个在配乐换气后整段重新进来的地方）。每个高潮固定这么处理：重拍前约 0.75 秒整个画面开始收暗；重拍前最后 3 帧画面静止；重拍那一帧把标题或锚词「砸」出来，配一个冲击音效。一收、一停、一放。

- **一拍一个动作**：小重音每一下让画面发生一件事（开场几下重音、中段的一串硬拍：模型跑一遍、计数牌跳一次）。

- 有配音（默认）时，时间表以旁白逐字对齐为主轴（见 voiceover-pipeline.md），镜头切换和高潮砸字落在旁白的关键词上，再把配乐重拍对到这些点附近；开头 3 秒的配乐按上面「开头 3 秒」的要求做最强一段。

- 没有配音（仅用户点名时），字幕就是旁白：每行字的停留至少按「字数 × 0.25 秒」给（读不完就延长或删字；这个系数按实际观感调）。

## D4：制作与自查

- 从 `_styles/<风格名>/template.html` 起步写 `index.html`，按 SKILL.md 第 5 步逐镜头做。

- 每个镜头做完渲静帧看；全部搭完跑 `qa_stills.py` 出每个镜头切走前一帧的拼图，再把两个高潮前后几帧单独渲出来拼一张（`render.py --still`）。逐张看：字有没有重叠、出画，该出现的有没有出现，高潮那一帧标题是不是已经亮了。

- 渲完跑 `scripts/still_check.py out/$NAME.mp4 --subs audio/subs.srt --allow <片尾预告起>-<总长>`：画面超过 2 秒不动、字幕换了画面没跟的地方，回去加动作再重渲那几秒（标准见 craft-rules.md）。

- **最多改三轮**，剩下的小问题写进交付报告，不无限打磨。

- 响度：混音 `audio_tools.py normalize` 到 -14 LUFS，`audio_tools.py check` 出数字，把被配乐盖住的音效单独列出来。**AI 听不到声音**，只报数字，交付时提醒用户戴耳机听一遍。

## D5：交付（全部放 `out/`）

1. `publish.txt`：按 SKILL.md 的三段格式，标题、简介、tags 取自 Gemini 的 `copy/copy.json`（已过 `check`）。标题 20 字内、第二人称 + 痛点、留悬念（「躲进掩体，为什么还被打死？」好过「掩体为什么挡不住子弹」）；简介第一句写钩子，再写这期要点；tags 一行 5 个以内，#Vibe知识大赏 打头。

2. 成片 `$NAME.mp4`。

3. 3:4 封面 `$NAME-封面.png`（1080×1440）：竖版片子把封面帧裁安全区（`ffmpeg -y -i cover-full.png -vf crop=1080:1440:0:240 out/$NAME-封面.png`）；横版片子单独用 `?cover=1` 页面按 1080×1440 重新排版渲一张（`render.py "index.html?cover=1" ... --size 1080x1440`），不要从 16:9 硬裁。封面上的标题和片内标题一致，缩到 360px 宽还看得清。

4. 字幕稿 `$NAME-字幕.txt`：按时间顺序的全部屏幕文字。

5. 交付报告 `report.md`：资料来源、哪些数字是自己算的、替用户做了哪些决定、对标原片学了什么没搬什么、剩下的小瑕疵、提醒用户戴耳机听。

6. 在手册「七、发布记录」表追加一行（日期、标题、对标原片、风格，6 小时数据留空等用户回填）。

## 改稿

用户按「位置 / 问题 / 目标 / 边界」提修改时，严格守住「边界」那一行（比如改天平时不动配乐和字幕的时间）。改动只渲用户说的那一帧给他看，确认了再改下一处，最后整片重渲。

## 数据结论写回哪里

用户丢来后台导出的作品数据、或要求拉数据时（用 `douyin_stats.py` 自己拉）：不看播放量，先看 2 秒跳出和 5 秒完播判断开头过没过关，再看收藏率、点赞率、分享率判断题选得对不对（第一轮数据：开头过关后，流量差距主要由收藏率和点赞率拉开）；找质量相近、流量差很多的几条对比，用选题三问解释差在哪，结论**追加进手册「六、数据结论」**（不改本文件）。下一期 D0 读到，就按新结论选题和起标题。
