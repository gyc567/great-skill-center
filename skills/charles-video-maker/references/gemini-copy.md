# 文案交给 Gemini 写

> 2026-10-22 起：视频里所有「给人听、给人看」的文字——旁白稿、画面关键词、标题、简介、tags——一律由本地 Gemini（Antigravity CLI `agy`）来写。原因：用户觉得 Claude 写的旁白太僵硬，书面腔重。
>
> 分工：**Claude 管事实和结构，Gemini 管说法。** Claude 写任务单（事实清单、每句的时长、画面在演什么），Gemini 写文案，Claude 只做硬校验，不合格就把问题反馈给 Gemini 重写。**Claude 不亲手改 Gemini 的措辞**——只有事实错误时，在反馈里指出让它改；实在要动，只改那几个字。

## 流程

1. **写任务单** `copy/brief.json`（格式见下）。事实只放查实过的，带出处；每个 slot 写清这句话出现时画面在演什么、最多几秒。
2. **生成**：`python3 scripts/gemini_copy.py gen copy/brief.json copy/copy.json`（约 30–60 秒）。
3. **硬校验**：`python3 scripts/gemini_copy.py check copy/brief.json copy/copy.json`。查：
   - 每句字数塞得进 slot（按任务单的 `cps` 字/秒算，标点不计）。`cps` 怎么填：走 1.25 倍配音流水线（tts.py 默认加速）填 **6.5**（实测约 6.7）；按 slot 卡时间、不加速的 edge-tts 填 **4.5**。填小了会把片子压得太短；
   - 旁白里出现的每个数字，都在事实清单里出现过（编数字一票否决）；
   - 标题 ≤ 20 字；tags 正好 5 个，抖音必带 `#Vibe知识大赏` 且放第一个；
   - 全角标点，没有用「」或引号包词语做强调。
4. **不合格就重写**：`gen ... --feedback copy/feedback.txt`，反馈里逐条写问题（哪一句、什么问题），最多两轮。两轮还不过，把最后一版和问题清单交给用户选。
5. **配音校对**：合成后跑 ASR（Lemo 的 `asr_check.py` 或 whisper）。听岔的句子（同音字、生僻说法）也反馈给 Gemini 换说法，不要自己硬改。
6. 通过后，`copy.json` 里的 `lines` 写进旁白稿（`lines.json` / `narration.txt`），`title / description / tags` 写进 `out/publish.txt`。

## brief.json

```json
{
  "platform": "douyin",
  "cps": 6.5,
  "topic": "这条视频讲什么（一句话）",
  "audience": "谁会刷到（例：刷知识视频的年轻人，对陶瓷不了解）",
  "angle": "角度 / 锚词 / 想让人带走的那个感觉",
  "facts": [{"text": "查实的事实，原样写数字", "source": "出处"}],
  "keep_terms": ["必须原样出现的专有名词，如 kaolin、景德年制"],
  "slots": [
    {"id": "L0", "role": "钩子", "scene": "这句出现时画面在演什么", "max_sec": 6.0}
  ],
  "reference": "对标原片的口播稿或画面字（可选，只学语气，不抄句子）",
  "notes": "其他要求（可选）"
}
```

`role` 常用：钩子、交代、转折、高潮前半句、高潮、重新定义、结尾提问。

**第一句用你加反常识起头（用户 2026-10-26 定，2026-10-28 改）**：L0 的 role 写成「钩子：一句大白话，你做主语，可以直接问观众（你觉得……会……吗），也可以直接说出一个和观众认知相反的事实；答案和数字紧跟在这一句或下一句，5 秒内说完，不说原因」。只有题目实在落不到观众身上时才换别的起法，并在报告里写明为什么。2026-10-28 教训：排行那条第一句写成「你身上挂着的出生排行标签，在两万多人的数据里，根本测不出性格差别」，用户说太拗口；问题出在一长串定语堆在主语前面。用户要的是像聊天一样直接问出来：你觉得在家排老几，会影响性格吗。

**抖音观众偏下沉，说法越直接越简单越好（用户 2026-10-28 定）**：整条文案都按这个写，不只是开头。一句只说一件事；能用大白话的词就不用书面词和术语，比如说排老几，不说出生排行；少加额外的名词和形容词，修饰语能删就删；不要把几个名词串成一长串定语；人名、机构名、调查名能不说就不说，非说不可就说一次，后面用这项研究。写 brief 时把这条写进 notes，Gemini 交稿后逐句检查，哪句拗口、名词堆叠，就在反馈里点名让它改得更白。

**任务单里别给例句**（2026-10-25 教训）：notes 里写了一句现成的钩子例句，Gemini 就照着句式写，一个系列 10 集的开头全成了一个模子，用户说僵硬、不像人说话。只写要达到的效果；要给语感参考，就给账号已发布、观众买账的片子的原句，写明只学语感不学句式。钩子的 max_sec 给到 6 秒左右，别卡 3 秒：硬塞常识加推翻加数字，只能写出碎片。要多个开头备选时，在 notes 里让它额外输出 `opening_options`。

**写完通读逻辑**：开头说过的数字，高潮别再假装揭晓（高潮要给新信息）；能照做的动作前面要有一句为什么；代入段里观众的失败瞬间，后面的反转要接回来；从出处过渡到实验要有一句引话头。另外 check 会把千万、万、百、千当数字，口语别用千万别。完整案例见 `~/Desktop/video/vibe-video/_series/bug/SERIES.md`。

## 给 Gemini 的提示词（`scripts/gemini_copy.py` 会把 brief 和反馈填进来）

```
不要调用任何工具、不要执行命令、不要上网查资料——事实只用任务单里给的，直接写完输出 JSON。

你是抖音知识短视频的口播文案作者。下面是一条视频的任务单（JSON）。请按每个 slot 写一句旁白，再写标题、简介和 5 个 tag。

怎么写：
- 写给耳朵听的，不是给眼睛看的。像在跟朋友聊一件你刚弄明白的事：短句、口语、有画面，能用「你」就用「你」。
- 别用书面腔和套话：不要「在……中」「随着……」「不仅……更……」「值得一提的是」「让我们」「今天我们来聊聊」，少用四字成语堆砌。
- 每句要和这个 slot 的画面对得上，观众是边看边听的；画面已经演出来的东西，嘴上可以少说。
- 第一句（钩子）是一句完整的人话：有主语有动作，像对朋友说话，反转靠语气推出来；不要标题腔，不要「X？Y。」这种标题腔的两截碎片（问观众一个完整的问题再接答案可以），不要用「你肯定也」「你是不是也」这类套话起头。前 5 秒内让人听到反差或那个具体数字，不要自我介绍、不要铺垫。第一句尽量用你做主语起头，可以像聊天一样直接问观众一个问题（你觉得……会……吗），也可以直接说出一个和观众原来的认知相反的事实：反常识的结果和数字就在这一句或紧接的下一句里，5 秒内说完；说出结果，不说原因，原因留给后面。不要写成你以为什么、其实什么这种自问自答。
- 抖音观众偏下沉，说法越直接越简单越好：一句只说一件事，用大白话的词，不用书面词和术语；少加额外的名词和形容词，不要把几个名词串成一长串定语；人名、机构名能不说就不说。
- 高潮前那句可以只说一半，停在破折号上。结尾抛一个人人都答得上来的问题，引到评论区。
- 事实只能用任务单 facts 里的，数字原样用，不许编新数字、新年份、新人名；keep_terms 里的词原样保留。
- 每句的字数要能在 max_sec 秒内念完（按每秒 4.5 个字算，标点不算）。宁短勿长。
- 避开容易听岔的同音说法（例：「过手」容易听成「裹手」，就改成「经过……双手」）。
- 标点一律中文全角；不要用引号或「」把普通词语括起来强调。
- 姿态是平视分享，不说教、不煽情过头。

标题：20 字以内，第二人称或问句，留悬念、不说答案。
简介：一段，第一句是钩子，接着两三句要点，口语化。
tags：正好 5 个，抖音的话第一个是 #Vibe知识大赏，其余挑和内容最贴、最有人搜的。

只输出一个 JSON 对象，不要任何解释，格式：
{"lines":[{"id":"<任务单里 slot 的 id，原样照抄，一个 slot 一句>","text":"..."}],"title":"...","alt_titles":["...","..."],"description":"...","tags":["#Vibe知识大赏","#...","#...","#...","#..."]}
```
